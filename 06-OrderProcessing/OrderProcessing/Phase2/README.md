## Phase 2 questions

1. **What is the difference between starting a task and awaiting it?**
   Calling an async method starts its operation and returns a `Task` representing its eventual completion. `await` asynchronously suspends the current method until that task completes; it does not synchronously block the current thread.

2. **Does every Task create a new thread? Does `Task.Delay()` use a thread while waiting?**
   No. A `Task` represents an operation or its result, not a dedicated thread. `Task.Delay()` uses a timer to complete the task later and does not keep a thread blocked for the entire delay.

3. **What happens if `.Result` or `.Wait()` is used on an unfinished task? Why is it dangerous?**
   The calling thread blocks until completion. In environments with a synchronization context, blocking can deadlock when the awaited continuation needs that blocked context. Blocking also wastes a thread. `BlockingWaitDemo.Run()` is the separate, deliberate demonstration; normal Phase 2 code uses `await`.

4. **What happens to an exception thrown inside a task that is never awaited?**
   The task stores the exception. If nobody observes the task or its exception, the failure can go unnoticed by the caller; it may later surface through `TaskScheduler.UnobservedTaskException`, but that is not a reliable error-handling strategy. Tasks should be awaited or otherwise observed.

5. **When should `Task.Run()` be used, and when should it be avoided?**
   It is appropriate for CPU-bound work that would otherwise occupy the calling thread, such as the invoice-rendering loop here. It should not be added around naturally asynchronous file, database, or network I/O; those APIs already yield while waiting.

6. **What is the difference between `Task` and `Task<T>`?**
   `Task` represents an operation with no returned value. `Task<T>` represents an operation that eventually produces a value of type `T`.

7. **Why can a `lock` block not contain `await`?**
   A `lock` uses a thread-affine monitor that must be exited by the same thread that entered it. An `await` may suspend and resume on another thread, so C# disallows `await` inside a `lock` block. Use an asynchronous coordination primitive such as `SemaphoreSlim.WaitAsync` when asynchronous mutual exclusion is required.

8. **Why did the unprotected stock reservation oversell, and how was it prevented?**
   Both unsafe operations read the same stock value (`1`) before either writes. After their delays, both write the stale result (`0`) and both report success. The safe implementation performs the stock check and decrement together inside `JsonFileStore.UpdateAsync`, whose per-file lock protects the entire read-modify-write operation. The second reservation sees stock `0` and returns `false`. Stock release uses the same atomic update approach.

## Why the invoice uses `Task.Run`

The 20,000,000-iteration rendering loop is CPU-bound, so `Task.Run` moves that computation to a ThreadPool thread instead of running it on the caller's thread. Database/file/network waits are I/O-bound and should use their asynchronous APIs directly; wrapping them in `Task.Run` would needlessly occupy a ThreadPool thread while waiting.
