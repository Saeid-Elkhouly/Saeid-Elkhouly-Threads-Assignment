1. Why are the synchronous and asynchronous times almost the same when orders are awaited one after another?

Both approaches process the orders sequentially. The next order does not start until the current order finishes, so the asynchronous version does not gain the concurrency benefits that would come from processing multiple independent orders at the same time.

await allows a thread to be released while an asynchronous operation is waiting, but it does not eliminate the simulated operation delays.

The measured times also depend on which operations are included in each measurement. In this implementation, the asynchronous path saves every validation result, while the synchronous comparison does not. Therefore, the asynchronous time includes additional simulated write delays and is not expected to be close to the synchronous time.

2. Is the thread ID before an await always the same as after it? Why?

No. The continuation after an await may execute on a different thread, depending on the execution context and the asynchronous operation.

The thread IDs printed by the application logger can be used as evidence. If the ID changes across an asynchronous operation, it shows that the continuation resumed on another thread. If it stays the same, that does not mean it must always stay the same.

3. What does the thread do while Task.Delay() and Thread.Sleep() are waiting?

Thread.Sleep() blocks the current thread for the specified duration. That thread cannot perform other work during the sleep.

Task.Delay() creates an asynchronous delay. When the method awaits it, the current thread can return to the thread pool and perform other work. The asynchronous method resumes when the delay completes, potentially on a different thread.

4. Why should a repository method return Task<T> instead of T?

A repository method that performs asynchronous I/O should return Task<T> so the caller can await its completion without synchronously blocking a thread while waiting.

The T represents the result produced when the operation completes. For operations that do not return a value, Task is appropriate.

5. What is the difference between File.ReadAllText() and File.ReadAllTextAsync()? Does the asynchronous version occupy a thread while the disk is reading?

File.ReadAllText() performs synchronous file reading and does not return until the operation finishes.

File.ReadAllTextAsync() provides an asynchronous API that can be awaited, allowing the calling method to suspend instead of blocking its thread while waiting for I/O.

The asynchronous API does not guarantee that no thread is involved anywhere in the underlying implementation. The important distinction is that the caller does not need to block a thread while awaiting completion.
